# 全量开发集上的反馈纠错比较

记录日期：2026-09-19。全部配置在本轮结果产生前确定。旧实验结果与源码不覆盖。

## 数据和结论范围

使用当前本地官方Spider开发集全部1034题和BIRD清理版（2025-11-06）开发集全部1534题；保留官方题目行，不按方法表现或难度抽样。各数据集分别报告。两套开发数据已有部分问题参与过方法设计，因此本轮是完整基准评估，不称独立盲测。另记录与历史样本的重合情况。

先保存公共任务和来源清单，再由独立评测端执行参考SQL。参考执行失败、超时或超过行数上限的题目保留清单，不替换、不修改参考答案。报告总样本数、可评分数及原因；不可评分题仍保留初答成本，主质量与成本配对分析使用共同可评分集合。另列全部请求的成本。

## 模型、反馈与计费

所有方法共用Qwen2.5-7B-Instruct现有本地4位量化初答；SQL修复使用原固定Qwen2.5-14B-Instruct本地4位量化版本。复用已有批处理后端、greedy、batch4；SQL输出上限1024、反馈上限2048、要求提取384，SHARE助手沿用3000及作者停止规则。实际版本由逐调用清单记录。

采用项目现有固定版本的官方Spider/BIRD单数据库执行匹配，逐轮返回相同二元反馈。只有拒绝后进入修复，接受后停止。生成端不读取正确SQL、参考结果或参考派生解释。这里不是Spider多数据库测试套件分数；与旧内部匹配反馈下的轨迹分别报告。

每条路径累计初答、所有助手、解释、批评、筛选、生成和失败调用的输入输出token。命中完全相同请求的真实历史输出也全额计费。只读数据库执行次数和用户交付次数另列，不计入LLM token。训练开销不冒充在线token；专用判别器的输入也单独记录，不能当作免费语言模型步骤。

## 方法和预算

目标主对照：SHARE、CRITIC、Self-Refine、Self-Debugging、Reflexion、CycleSQL。DIN-SQL纠错模板与CHESS选字段组件保留为扩展对照。各方法注明原论文实现范围及为共同二元反馈协议所作的适配。CycleSQL必须核查作者的数据来源解释和验证器；缺少关键组件不得将简单提示称作完整CycleSQL，缺项单独报告。

当前ReLink-SQL流程不改：一轮结构筛选重答、两轮直接修改、独立问题要求、最多一条程序修改交付，以及必要时一次完整生成。最多五次修复交付，两次尾部模型调用；程序失败后生成输入沿用当前版本，不因新结果调整规则。

主比较预先固定最多五次修复交付，分别报告1至5轮结果。论文基线另探索至八轮，不因连续几轮没有提升而提前停止；接受后停止，超过后端上下文上限的请求明确记录为技术失败，不截断或换题。当前方法第5阶段后保持终止状态，不凭空增加操作。

不同预算的完整阶段点是主要结果；相近正确率的事后停止回放仅作为描述性分析，不当作在新数据上预先选定策略的成绩。不存在按未来正确性选择分支或候选。

## 实施顺序与复核

准备完整公开清单与参考执行审计，同时生成共同初答。新增方法先用公开身份选出的少量现有题检查接口、反馈隔离、逐步账本和断点续跑，不据此调优提示。随后在完整数据上运行当前方法和全部可复现对照。新增方法的来源、模板、关键权重与适配差异在运行前保存。

检查初答一致、接受后不再调用、每轮只交付规定数量、程序候选不读取参考答案、所有实际调用和失败尝试计费、旧结果及受保护源码不变。每个阶段完成后提交输出及哈希；未完成阶段不计入最终表。原始失败记录保留，技术错误修复需要明确记录，不能覆盖已完成实验。

清理仅删除确认无依赖的缓存、临时产物和新实现中的重复逻辑；历史复现依赖、数据、论文源码与模型权重保留。
