# 论文方法的实现范围

本文档在新增方法推理前确定。统一采用准确二元用户反馈、共同初答和生成模型；不将这些适配后的成绩称为原论文完整系统的排行榜成绩。

| 方法 | 本轮实现 | 来源 |
|---|---|---|
| ReLink-SQL | 原结构筛选重答、两次直接修改、原独立要求与程序候选、原完整生成；核心函数直接导入，不重新设计 | iteration15当前版本 |
| SHARE | 作者三类助手权重、原五阶段提示及停止规则；只在用户拒绝后调用，作者提示不额外插入纠错历史；本地生成器统一为Qwen2.5-14B | [SHARE](https://arxiv.org/abs/2506.00391)，沿用iteration13的作者提示实现 |
| CRITIC | 实际执行报告→模型批评→完整SQL修改，保留此前批评和拒绝SQL | [CRITIC](https://arxiv.org/abs/2305.11738)，沿用已有SQL适配 |
| Self-Refine | 模型反馈→完整SQL修改，不提供执行报告，保留历史反馈 | [Self-Refine](https://arxiv.org/abs/2303.17651)，沿用已有SQL适配 |
| Self-Debugging | 采用附录E.7聊天零样本流程：解释当前SQL及实际执行→解释问题要求→比较两者并修复；三次调用均计费 | [Teaching Large Language Models to Self-Debug](https://arxiv.org/abs/2304.05128)，方法与提示摘录见sources |
| Reflexion | 将执行报告及用户拒绝转为反思，再结合反思生成SQL；此前反思形成跨轮文字记忆 | [Reflexion](https://arxiv.org/abs/2303.11366)，复用已保存的SQL迁移模板 |
| DIN-SQL | gentle纠错模板，不包含原论文完整分解生成流程，作为扩展对照 | [DIN-SQL](https://arxiv.org/abs/2304.11015) |
| CHESS | 作者列筛选提示及本地SQL修复组件，不包含原论文完整四代理流程，作为扩展对照 | [CHESS](https://arxiv.org/abs/2405.16755) |

Self-Debugging的前两次调用保留附录E.7顺序：先解释SQL及最多两行实际结果，再解释问题。第三次调用加入共同的二元拒绝信号，并明确要求交付完整SQL；此前拒绝的SQL作为可用历史提供。没有使用标准答案、参考返回类型或参考解释。解释不是我们的独立要求提取：其问题解释在聊天上下文中可见旧SQL及SQL解释。原论文已讨论解释问题和比较SQL语义，因此不能声称“把问题要求单独表示”本身是首创。

Reflexion的SQL迁移模板来自项目已保存的作者编程任务实现适配，实际SQL执行替代Python测试记录。不能将成功执行当作语义正确。每次反思和后续生成均含已有反思记忆；记忆输入重复发送时再次计费。没有给模型额外的正确答案提示。

## CycleSQL的复现状态

已核查[作者仓库](https://github.com/Kaimary/CycleSQL)，提交2cb4c16d3576a0e97a2fe5efebc80403dd2a3468。原实现通过数据来源和操作语义生成解释，再用训练后的自然语言推断分类器检查候选；主脚本从多个生成候选中选择，不能用“解释后重写”两句话替代。作者脚本还包含读取gold作诊断的代码，实际接入时必须隔离这部分，不能直接将含gold的数据送入修复进程。

本次尝试作者公开的分类器权重链接，下载地址返回404，预览地址返回403；公开仓库没有data/nli/train.json，Hugging Face按CycleSQL检索没有找到模型。因此目前缺少可验证的关键权重，完整CycleSQL保持待补，不给出虚构成绩，也不以其他分类器替代后继续使用完整方法名称。访问记录保存在sources/cyclesql_weight_checks.json。

这不会阻塞其它方法。报告明确区分已运行、运行中和因外部依赖待补的方法。
