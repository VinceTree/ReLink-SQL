# 逐题结果字段说明

每个 CSV 对应一种方法或参数设置。每个文件为 1,529 题。E3 词法列数 4 和直接修订 2 次的基线均使用 `E1_ReLink.csv`，不重复导出。

| 字段 | 含义 |
|---|---|
| `task_id` | 原始题目 ID，可用于跨文件逐题配对。 |
| `database` | BIRD 数据库名称。 |
| `initial_correct` | 初答是否通过，1 为通过、0 为未通过。 |
| `r1_correct` … `r5_correct` | 该阶段结束时是否已经通过；已通过的结果会沿用，因此这是累计状态，不是各阶段新增数。r4 不一定实际提交 SQL。 |
| `final_correct` | 最终是否通过。 |
| `first_correct_stage` | 首次通过阶段；`r0` 为初答；空白表示最终未通过。 |
| `repair_calls` | 最终路径使用的修复模型调用次数，包含从其他实验精确复用的调用。 |
| `repair_attempts` | 路径调用次数加本运行记入该题的失败尝试；不能用来推断账号总请求数。 |
| `repair_method_tokens` | 该题路径修复模型输入加输出的方法侧 token；不含初答。 |
| `path_total_token_units` | 初答及修复的路径总计；E1/E1b/E3 混合 Qwen 与 GPT 分词器，不能视为单一分词器口径。 |
| `path_reported_codex_input` / `path_reported_codex_output` | 路径关联调用及已记录失败的 Codex 用量；输入包含缓存。若关联尝试未返回用量，字段为空，不表示零。复用调用仍计入路径，所以这些字段不能相加得到本次实际新增账号用量。 |
| `sum_call_seconds` | 路径调用及已记录失败的耗时之和；复用调用沿用原时间，不是本实验端到端墙钟时间。 |

累计状态和 token 来自原封存逐题路径及指标。导出时核对了题目 ID、阶段顺序、通过状态不回退和最终通过数；原始 SQL、结果集、提示词、模型回复及完整账本不在本包内。

逐题 CSV 为带 BOM 的 UTF-8；`02_结果表/` 保持原始 UTF-8 字节。Excel 打开中文若显示异常，请通过“数据导入”选择 UTF-8。

`E2b_CRITIC.csv` 使用 E2 的 GPT 初答，初答和修复均按 `o200k_base` 计数。`path_total_token_units` 包含复用的初答；`path_reported_codex_input` / `path_reported_codex_output` 只含修复相关调用，不含初答。实际新增账号用量以 E2b 账本汇总为准。
